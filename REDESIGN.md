# Redesign

I want to completely redesign my systems to be a fully cohesive and user-streamlined. I want to create a full computing suite that can be hosted on as little as one machine to as many as a whole home datacenter. The core design philosophy is based on the actor model used by languages like Erlang and Elixir, with programs being actors. It will also use Nix/NixOS to be a completely declarative and resilient system. It's also going to have a focus on local first, with any actor (program) being able to run on any machine, so it could be entirely locally hosted if you want, though some features will be rendered useless as it isn't always on. Another thing I want to do is to have any program installed by default to be a fork of the original, so I have copies of all dependencies, as well as being able to add patches to better fit in the system. I want to re-create many applications to be built on the BEAM VM, so they can be split across multiple machines if needed, and be localized automatically. Things like the calendar app should be re-written to be TUI based and so that it can either run as a local system (data stored locally, alerts processed locally, etc.) or as a distributed always-on system, like with a server and a computer, which will then simply connect the BEAMs and allow it to automatically localize the UI vs the backend. That's kind of the design I want for the entire system and for basically every app. Since I do have servers, I want all the data storage to be on the servers, with only needed data being sent/updated on the client. Basically, if the system can boot Linux and render the display, then it can be used with every service once it gets connected to another system, since everything could just run on the remote system and just get the UI updates from the server. There should be an automatic system for wrapping nix-packages in a microvm so that they can be treated like actors (running local if possible, else on the server with UI updates) while also being securely installed/run. I also want all the apps to be fully UI customizable, so one of the first projects will be to make a graphics library that allows for standardized theming across all apps (colors, etc), with app specific values that can be set too (UI element position, text, etc).

I want to achieve all this via a mix of custom-tuned smaller AI models to handle most of the work, leaving the management/fine-design to larger AI models such as Sonnet or Opus, though I'd like to investigate local models and the compute required to run them. Likewise, I want to set up a "collaborative" environment for quickly iterating designs and review changes. Furthermore, I want all models to use Grug-Brained developer speak (why use many when few word work) to reduce token count. That includes for code comments and everything. My goal is to be able to orchestrate projects from a high-level, down to pseudocode and design docs. I basically want to use the larger models to create the most immaculate documentation ever, and then use simple, tuned models to actually implement it in code. Everything should have pseudocode, descriptions, fault analysis, everything that a well-engineered system should do, rather than just building blindly. I also want to try to automate and integrate the agents into the entire system, basically reducing using the computer down to a text input. That can be either a command (to run a program) or a prompt to the AI system to make a change. Also, agents should have the minimal-context required to do the job, so I'm thinking of having agents that organize the contexts and then feeding that into the actual programming agents. The graph of agent hierarchy should mainly match structure of the program, down to a function level. An example branch would be `Me -> Project Owner (Calendar,..) -> System Manager (UI/UX*,IO,Integration,..) -> System Manager (TODO Integration,Day Render,Storage,...) -> Task Manager (Implement X,Update Y,...) -> Application Specific AI (ASAI) (Planner/Visulizer,Designer,Programmer,...)`, with helper agents for managing context and for command-line/system integration.
